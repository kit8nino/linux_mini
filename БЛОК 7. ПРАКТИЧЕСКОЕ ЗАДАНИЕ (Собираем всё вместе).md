## 7.1. Постановка задачи

Представьте, что вы администрируете веб-сервер. На нём крутятся:
- **Nginx** (веб-сервер),
- **MySQL** (база данных),
- **SSH** (доступ по SSH).

Ваша задача — написать скрипт, который:
1. **Проверяет**, работают ли эти сервисы (по имени процесса или по проверке порта).
2. **Если сервис не работает** — перезапускает его (через `systemctl restart` или `service`).
3. **Записывает** в лог-файл каждую проверку: время, статус каждого сервиса, а также текущую загрузку CPU и использование памяти.
4. **В случае сбоя** пишет в лог отдельное предупреждение с указанием, какой сервис упал и перезапущен.
5. **Запускается автоматически** каждые 5 минут через cron.
6. **Пишет понятные сообщения** и умеет обрабатывать ошибки (не падает, если сервис не установлен).

**Объяснение:**

- Переменная `LOG_FILE` — путь к логу (убедитесь, что у пользователя, от которого запускается скрипт, есть права на запись; если нет — используйте `~/monitor.log`).
- `SERVICES` — массив с именами сервисов (для systemd). Можно добавить и другие.

### Шаг 2. Функция логирования

Сделаем функцию, которая пишет в лог с временной меткой и принимает произвольное количество аргументов.

```bash
# Логирование сообщения в файл и на экран (если запущено интерактивно)
log() {
    local timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    local message="$*"
    echo "[$timestamp] $message" | tee -a "$LOG_FILE"
}
```

- `tee -a` — выводит и на экран, и добавляет в файл. Полезно при ручном запуске, чтобы видеть происходящее.
- Если вы хотите писать только в лог (без экрана), уберите `tee -a` и оставьте `echo ... >> "$LOG_FILE"`.

### Шаг 3. Функция проверки одного сервиса

Напишем функцию, которая принимает имя сервиса, проверяет его статус, и если он неактивен — перезапускает и возвращает 1 (сбой). Если работает — возвращает 0.

```bash
# Проверка и перезапуск сервиса
check_service() {
    local service="$1"
    local status=0

    # Проверяем, запущен ли процесс (используем pgrep, если сервис не systemd)
    if pgrep -x "$service" > /dev/null 2>&1; then
        log "Сервис $service: РАБОТАЕТ"
        return 0
    else
        log "ВНИМАНИЕ! Сервис $service НЕ РАБОТАЕТ. Пытаюсь перезапустить..."
        # Пытаемся перезапустить через systemctl
        if systemctl restart "$service" 2>/dev/null; then
            log "Сервис $service перезапущен успешно."
            # Проверим, действительно ли запустился после перезапуска
            sleep 2
            if pgrep -x "$service" > /dev/null 2>&1; then
                log "Сервис $service теперь работает."
                return 0
            else
                log "ОШИБКА: Сервис $service не запустился после перезапуска!"
                return 1
            fi
        else
            log "ОШИБКА: Не удалось перезапустить $service (возможно, не установлен или нет прав)."
            return 2
        fi
    fi
}
```

**Важные нюансы:**
- Мы используем `pgrep -x` для точного совпадения имени процесса. Некоторые сервисы могут называться по-другому (например, `mysqld`). В реальности лучше проверять через `systemctl is-active --quiet`, но для учебных целей оставим `pgrep`.
- Если сервис не управляется systemd, используйте `/etc/init.d/$service restart` или `service $service restart`.
- Проверка через `pgrep` не всегда надёжна (может быть несколько процессов с одним именем). Для критичных сервисов лучше проверять сетевой порт (например, с помощью `nc -z localhost 80` для nginx). Я покажу оба подхода.

**Альтернативная проверка через порт (добавим как отдельную функцию позже):**
```bash
check_port() {
    local host="$1"
    local port="$2"
    nc -z "$host" "$port" 2>/dev/null
}
```

### Шаг 4. Функция сбора системной статистики

Добавим сбор нагрузки CPU и памяти для записи в лог.

```bash
# Получить загрузку CPU (среднее за 1 минуту) и использование памяти
get_system_stats() {
    local load=$(uptime | awk -F'load average:' '{print $2}' | awk -F',' '{print $1}' | xargs)
    local mem_total=$(free -m | awk '/Mem:/ {print $2}')
    local mem_used=$(free -m | awk '/Mem:/ {print $3}')
    local mem_percent=$((mem_used * 100 / mem_total))
    echo "CPU нагрузка: $load, Память: $mem_used/${mem_total}MB ($mem_percent%)"
}
```

Эта функция возвращает строку, которую мы позже передадим в `log`.

### Шаг 5. Основной цикл по всем сервисам

Теперь напишем основной код, который проходит по массиву `SERVICES`, проверяет каждый, фиксирует сбои и пишет итоговый отчёт со статистикой.

```bash
# ------------ Основной блок ------------
log "======= НАЧАЛО ПРОВЕРКИ ======="

# Собираем статистику до проверки
stats=$(get_system_stats)
log "Система: $stats"

# Переменная для подсчёта ошибок
error_count=0

# Проверяем каждый сервис
for svc in "${SERVICES[@]}"; do
    if check_service "$svc"; then
        # Всё хорошо
        :
    else
        # Если функция вернула не 0, увеличиваем счётчик ошибок
        ((error_count++))
    fi
done

# Итоговое сообщение
if [ $error_count -eq 0 ]; then
    log "Все сервисы работают корректно."
else
    log "ЗАВЕРШЕНИЕ С ОШИБКАМИ: $error_count сервисов имели проблемы (см. выше)."
fi

log "======= КОНЕЦ ПРОВЕРКИ =======\n"
```

### Шаг 6. Полный скрипт (собираем всё вместе)

Ниже представлен готовый скрипт `monitor.sh` с комментариями. Скопируйте его, сохраните, сделайте исполняемым (`chmod +x monitor.sh`).

```bash
#!/bin/bash
# monitor.sh – универсальный мониторинг сервисов
# Версия 1.0

set -euo pipefail

# ----------------- Конфигурация -----------------
LOG_FILE="/var/log/monitor.log"
# Список сервисов для проверки (имена процессов, которые ищем pgrep)
SERVICES=("nginx" "mysqld" "sshd")
# Для проверки через порт можно добавить ассоциативный массив, но оставим простой вариант.
# -------------------------------------------------

# Функция логирования
log() {
    local timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    local message="$*"
    echo "[$timestamp] $message" | tee -a "$LOG_FILE"
}

# Функция проверки сервиса (по имени процесса)
check_service() {
    local service="$1"
    if pgrep -x "$service" > /dev/null 2>&1; then
        log "Сервис $service: РАБОТАЕТ"
        return 0
    else
        log "ВНИМАНИЕ! Сервис $service НЕ РАБОТАЕТ. Перезапуск..."
        # Пытаемся перезапустить (systemctl, если не сработает – service)
        if systemctl restart "$service" 2>/dev/null || service "$service" restart 2>/dev/null; then
            sleep 2
            if pgrep -x "$service" > /dev/null 2>&1; then
                log "Сервис $service перезапущен и работает."
                return 0
            else
                log "ОШИБКА: Сервис $service не запустился после перезапуска."
                return 1
            fi
        else
            log "КРИТИЧЕСКАЯ ОШИБКА: Не удалось перезапустить $service (возможно, не установлен)."
            return 2
        fi
    fi
}

# Функция сбора статистики системы
get_system_stats() {
    local load=$(uptime | awk -F'load average:' '{print $2}' | cut -d',' -f1 | xargs)
    local mem_total=$(free -m | awk '/Mem:/ {print $2}')
    local mem_used=$(free -m | awk '/Mem:/ {print $3}')
    local mem_percent=$((mem_used * 100 / mem_total))
    echo "CPU: $load, RAM: $mem_used/${mem_total}MB ($mem_percent%)"
}

# ------------ Основной блок ------------
log "======= НАЧАЛО МОНИТОРИНГА ======="

# Статистика
stats=$(get_system_stats)
log "Состояние системы: $stats"

error_count=0
for svc in "${SERVICES[@]}"; do
    if ! check_service "$svc"; then
        ((error_count++))
    fi
done

# Итоговый отчёт
if [ $error_count -eq 0 ]; then
    log "Все сервисы в норме."
else
    log "Обнаружено проблем: $error_count (смотри выше)."
fi

log "======= ЗАВЕРШЕНО =======\n"
```

### Шаг 7. Тестирование скрипта

Перед тем как добавлять в cron, протестируйте вручную.

1. **Запустите вручную:**
   ```bash
   ./monitor.sh
   ```
   Посмотрите вывод на экран и проверьте файл лога: `cat /var/log/monitor.log`.

2. **Имитируйте сбой:**
   Остановите один из сервисов, например, `sudo systemctl stop nginx`. Затем запустите скрипт. Он должен обнаружить остановку, перезапустить nginx и записать предупреждение.

3. **Проверьте права на запись лога:**
   Если вы запускаете скрипт от обычного пользователя, а лог в `/var/log/`, то у вас может не быть прав. Временно используйте `LOG_FILE="$HOME/monitor.log"` или запустите скрипт через `sudo`.

### Шаг 8. Автоматизация через cron

Теперь настроим запуск каждые 5 минут.

1. Откройте crontab текущего пользователя (или root, если скрипт должен иметь права на перезапуск сервисов):
   ```bash
   sudo crontab -e
   ```
   (Если используете root, то скрипт будет иметь полные права. Если хотите от обычного пользователя, но с sudo, используйте `sudo` внутри скрипта, но это сложнее.)

2. Добавьте строку (для root):
   ```bash
   */5 * * * * /full/path/to/monitor.sh >> /var/log/monitor_cron.log 2>&1
   ```
   *Замените `/full/path/to/` на реальный путь к вашему скрипту.*

   Объяснение:
   - `*/5` — каждые 5 минут.
   - `>> /var/log/monitor_cron.log 2>&1` — перенаправляем весь вывод (включая ошибки) в отдельный лог-файл, чтобы видеть, что cron выполнил скрипт.

3. Проверьте, что cron работает: через 5 минут посмотрите лог `monitor_cron.log` и основной лог `monitor.log`.

**Важно:** В cron окружение минимальное, поэтому все команды в скрипте должны использовать абсолютные пути (например, `/usr/bin/pgrep` вместо `pgrep`). В нашем скрипте мы использовали `pgrep`, `systemctl`, `service` — они обычно находятся в стандартных путях, но на всякий случай в начале скрипта можно добавить `export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`.

## 7.3. Расширения и улучшения (для самостоятельной работы)

5. **Проверка доступности сайта:** Для nginx можно выполнить HTTP-запрос `curl -f http://localhost` и проверять код ответа.

6. **Параметры командной строки:** Сделайте так, чтобы можно было запускать скрипт с аргументом `--check-only` (только проверять, не перезапускать) или `--services "nginx mysql"` (проверять только указанные).

## 7.4. Типичные ошибки и их решение

| Ошибка | Причина | Решение |
| :--- | :--- | :--- |
| `pgrep: command not found` | В cron нет полного PATH. | Используйте абсолютный путь `/usr/bin/pgrep` или задайте PATH в скрипте. |
| `Permission denied` при записи лога. | У пользователя нет прав на запись в `/var/log/`. | Используйте `sudo` для запуска или измените путь лога на `/tmp/monitor.log` (но это небезопасно). |
| Скрипт не перезапускает сервис, хотя `systemctl` работает. | В cron окружение не содержит `DBUS_SESSION_BUS_ADDRESS`. | Используйте `sudo systemctl` или задайте переменную `DBUS_SESSION_BUS_ADDRESS` в скрипте. Либо используйте `service` вместо `systemctl`. |
| Скрипт запускается, но ничего не пишет в лог. | Не создан файл лога, нет прав на запись в каталог. | Создайте файл вручную и дайте права: `sudo touch /var/log/monitor.log && sudo chmod 666 /var/log/monitor.log` (небезопасно, лучше дать права группе). |
| `pgrep` находит лишние процессы (например, `nginx` vs `nginx-helper`). | Используйте точное совпадение `-x`. Убедитесь, что имя процесса совпадает с именем сервиса. | Иногда имя процесса отличается от имени сервиса (mysqld vs mysql). Исправьте в массиве `SERVICES`. |
