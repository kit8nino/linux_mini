
**Цель блока:** Дать вам набор «рефлексов» и трюков, которые вы будете использовать автоматически. Это как слепой набор текста — сначала сложно, потом пальцы помнят. Мы разберем алиасы, историю, настройку окружения, работу с man-страницами, отладку, защиту от дурака и культуру написания скриптов.

## 7.1. Алиасы (псевдонимы) — ваши личные горячие клавиши

Алиас (alias) — это короткое имя для длинной команды с флагами. Вы задаете их один раз и забываете о многословии.

**Где хранить:** В файле `~/.bashrc` (или `~/.bash_aliases`, если вы подключили его в `.bashrc`). После редактирования выполните `source ~/.bashrc`, чтобы применить изменения в текущей сессии.

**«Cвятые» алиасы (скопируйте и пользуйтесь):**
```bash
# Навигация и листинг
alias ll='ls -alh'                 # Всё, подробно, с человеческими размерами
alias la='ls -A'                   # Все файлы, кроме . и ..
alias l.='ls -d .*'                # Только скрытые файлы
alias ..='cd ..'                   # Подняться на уровень вверх
alias ...='cd ../..'               # На два уровня вверх
alias ~='cd ~'                     # Быстро в домашнюю папку

# Управление процессами
alias psg='ps aux | grep -v grep | grep -i'   # Поиск процесса (пример: psg nginx)
alias htop='htop'                  # Если он установлен

# Работа с сетью
alias myip='curl -s ifconfig.me'   # Внешний IP
alias ports='netstat -tulpn | grep LISTEN'  # Слушающие порты

# Безопасность
alias rm='rm -i'                   # Запрос подтверждения перед удалением (спасает от случайностей)
alias cp='cp -i'                   # Запрос перед перезаписью
alias mv='mv -i'                   # Запрос перед перезаписью

# Удобства для разработчиков
alias gs='git status'
alias gl='git log --oneline --graph --decorate'
alias dc='docker compose'
alias k='kubectl'
```

**Важное предостережение:** Алиас `rm='rm -i'` может вас раздражать, когда вы уверены, что удаляете временные файлы. Чтобы его переопределить для одной команды, используйте `\rm -rf tmp/` (обратный слеш отключает алиас). Или просто привыкните — лучше лишний раз нажать `y`, чем удалить нужное.

## 7.2. История команд — ваша база знаний

Команда `history` хранит всё, что вы вводили. Это не просто список — это ваш дневник.

**Полезные настройки (добавьте в `~/.bashrc`):**
```bash
export HISTSIZE=10000          # Хранить 10000 команд в памяти
export HISTFILESIZE=20000      # Хранить 20000 команд в файле ~/.bash_history
export HISTCONTROL=ignoreboth  # Игнорировать дубли и команды с пробелом в начале
export HISTTIMEFORMAT="%F %T " # Добавить временные метки к истории
```

**Техники работы с историей (выучите наизусть):**

| Действие | Комбинация/команда | Пример |
| :--- | :--- | :--- |
| Поиск по истории (интерактивный) | `Ctrl + R` | Начните печатать `nginx`, и `bash` покажет последнюю команду с этим словом. Нажимайте `Ctrl+R` снова для предыдущих совпадений. |
| Повтор последней команды | `!!` | Набрали `apt install` без `sudo`? `sudo !!` выполнит прошлую команду с `sudo`. |
| Повтор команды по номеру | `!123` | `history` показал номер 123 — выполняем. |
| Повтор последней команды, начинающейся с... | `!apt` | Выполнит последнюю команду, начинающуюся с `apt`. |
| Вставить последний аргумент из прошлой команды | `Alt + .` (или `Esc`+`.`) | Было: `ls /var/log/nginx/`. Теперь печатаете `cd ` и жмёте `Alt+.` → получится `cd /var/log/nginx/`. |
| Удалить команду из истории | `history -d 123` | Удалить запись №123. |

**Секретный трюк:** Если вы поставите **пробел** в начале команды, она **не попадёт в историю** (при условии `HISTCONTROL=ignoreboth`). Это удобно, когда вы вводите пароль в явном виде или запускаете секретную команду, которую не хотите оставлять в логах.

## 7.3. Автодополнение (Tab-завершение) — ускоряем печать

Вы уже знаете, что `Tab` дополняет имена файлов. Но в Bash можно настроить контекстное дополнение для многих команд.

**Установите `bash-completion`:** (обычно уже стоит)
```bash
# Debian/Ubuntu
sudo apt install bash-completion
# CentOS/RHEL
sudo yum install bash-completion
```
После этого `Tab` будет работать для:
- `git` (ветки, теги),
- `systemctl` (имена сервисов),
- `ssh` (имена хостов из `~/.ssh/config`),
- `docker` (контейнеры, образы),
- и многих других.

**Правило двойного `Tab`:** Если нажать `Tab` дважды, bash покажет все возможные варианты, если их много.

## 7.4. Man-страницы и `--help` — учимся сами

Вместо того чтобы спрашивать коллегу, используйте встроенную документацию.

- `command --help` (или `-h`) — краткая справка для большинства утилит (GNU-стиль).
- `man command` — полноценное руководство (manual). Навигация: стрелки, `PageUp/Down`, `/` для поиска, `q` для выхода.
- `info command` — более детальная документация для сложных программ.

**Как быстро найти нужный флаг:** В `man` нажмите `/`, введите ключевое слово (например, `recursive`) и нажимайте `n` для следующего совпадения. Выход — `q`.

**Совет:** Существует сайт [tldr.sh](https://tldr.sh/) — это упрощённые примеры для команд. Установите `tldr` (`npm install -g tldr` или через пакетный менеджер) и используйте `tldr tar` — получите самые частые примеры без лишней теории.

## 7.5. Отладка и безопасное выполнение скриптов

Никогда не запускайте скрипт «вслепую», особенно если он делает опасные вещи (удаление, перезапись, изменение конфигов).

**Режим «сухого прогона» (dry-run):**
Для многих команд есть флаг `--dry-run`, `--simulate`, `-n`. Используйте его, чтобы увидеть, что будет сделано, но не выполнять.
```bash
# Удаление файлов старше 30 дней (показать, что найдётся)
find /tmp -name "*.tmp" -mtime +30 -delete -print   # -print покажет, что удалится, но мы убрали -delete
# Или с флагом -n для некоторых команд
rsync -avn --delete source/ dest/   # -n = dry-run
```

**Отладка скриптов (режим трассировки):**
- Запуск скрипта с `bash -x script.sh` — покажет каждую команду с подстановкой переменных.
- Если нужно отладить только часть скрипта, оберните её в `set -x` и `set +x`.

**Проверка синтаксиса:**
`bash -n script.sh` — просто проверит синтаксис (закрыты ли кавычки, скобки, нет ли ошибок), ничего не выполняя.

**Бэкап перед изменением:** Если вы правите конфиг, всегда создавайте бэкап:
```bash
cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak
# или используйте sed -i.bak, который автоматически создаст .bak
sed -i.bak 's/old/new/g' /etc/nginx/nginx.conf
```

## 7.6. Перенаправление потоков (STDERR и STDOUT) — очищаем вывод

Вы уже знаете про `2>&1`. Вот как это применяется в повседневности:

- **Выкинуть всё в /dev/null (подавить вывод):**
  `command > /dev/null 2>&1` — ничего не увидите на экране (ни ошибок, ни результата). Используйте осторожно.

- **Писать только ошибки в файл, а нормальный вывод на экран:**
  `command 2> error.log` — на экране увидите только успешный вывод.

- **Разделить потоки:**
  `command > stdout.log 2> stderr.log` — отдельно логи и отдельно ошибки.

## 7.7. Управление заданиями (jobs) — многозадачность без tmux

В одном терминале можно запустить несколько задач и переключаться между ними:

```bash
sleep 100 &                  # Запуск в фоне
jobs                         # Покажет список задач
fg %1                        # Вернуть задачу №1 на передний план
bg %2                        # Запустить задачу №2 в фоне (если она была приостановлена)
```

**Полезно при работе с `less` или `vim`:** Нажмите `Ctrl+Z`, чтобы временно приостановить редактор, выполнить пару команд в консоли, затем `fg` и продолжить редактирование.

## 7.8. Переменные окружения и `~/.bashrc` — настройка под себя

Ваш `~/.bashrc` — это скрипт, который выполняется при каждом запуске интерактивного bash. Используйте его для:
- Установки `PATH` (чтобы ваши скрипты были доступны без полного пути).
- Экспорта переменных (например, `EDITOR=vim`, `JAVA_HOME`).
- Загрузки алиасов.
- Определения функций (например, `mkcd() { mkdir -p "$1" && cd "$1"; }`).

**Функция `mkcd` (создать папку и сразу перейти в неё):**
```bash
mkcd() {
    mkdir -p "$1" && cd "$1"
}
```
Добавьте её в `.bashrc` и используйте: `mkcd new_project`.

**Установка `PATH`:**  
Если вы создали папку `~/bin` и складываете туда свои скрипты, добавьте в `.bashrc`:
```bash
export PATH="$HOME/bin:$PATH"
```

**Применение изменений:** После редактирования `.bashrc` выполните `source ~/.bashrc` или откройте новый терминал.

## 7.9. Клавиатурные сокращения (Emacs-режим в bash)

Bash по умолчанию использует стиль Emacs. Вот самые эффективные сочетания:

| Сочетание | Действие |
| :--- | :--- |
| `Ctrl + A` | Перейти в начало строки. |
| `Ctrl + E` | Перейти в конец строки. |
| `Ctrl + K` | Удалить всё от курсора до конца строки. |
| `Ctrl + U` | Удалить всё от начала до курсора. |
| `Ctrl + W` | Удалить слово перед курсором. |
| `Ctrl + Y` | Вставить то, что удалили (вставить). |
| `Ctrl + L` | Очистить экран (аналог `clear`). |
| `Ctrl + D` | Закрыть терминал (или отправить EOF). |
| `Ctrl + C` | Прервать текущую команду (SIGINT). |
| `Ctrl + Z` | Приостановить команду (SIGTSTP). |

Научитесь пользоваться `Ctrl+A`, `Ctrl+E`, `Ctrl+K` — это ускоряет редактирование длинных команд в разы.

## 7.10. Регулярные выражения в `grep`, `sed`, `awk` — базовая магия

Вам не нужно знать все регекспы, но основы пригодятся.

- **`.`** — любой один символ.
- **`*`** — ноль или более повторений предыдущего символа.
- **`+`** — одно или более (требуется `-E` в grep).
- **`?`** — ноль или один (требуется `-E`).
- **`^`** — начало строки.
- **`$`** — конец строки.
- **`[0-9]`** — любая цифра.
- **`[a-zA-Z]`** — любая буква.
- **`\b`** — граница слова.

**Примеры:**
- Найти все строки, начинающиеся с `Error`: `grep "^Error" log.txt`
- Найти все строки, заканчивающиеся на цифру: `grep "[0-9]$" log.txt`
- Заменить все даты вида `2023-01-01` на `01/01/2023` в sed:  
  `sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\3\/\2\/\1/g'`  
  (здесь используются группы в скобках и обратные ссылки `\1`, `\2`, `\3`).

## 7.11. Работа с большими объёмами данных: `xargs` и `parallel`

Если у вас есть список файлов или строк, и для каждого нужно выполнить команду, используйте `xargs` (или `parallel` для параллельной обработки).

**Базовый `xargs`:**
```bash
# Удалить все .log файлы, найденные find
find /tmp -name "*.log" | xargs rm -f

# Скачать все URL из файла
cat urls.txt | xargs -n1 wget
```

**Флаг `-P N`** в `xargs` (не во всех версиях) позволяет запускать N процессов параллельно:
```bash
cat urls.txt | xargs -P 4 -n1 wget   # Скачивать 4 URL одновременно
```

**GNU Parallel** — мощный инструмент, установите его: `sudo apt install parallel`. Пример:
```bash
parallel wget ::: $(cat urls.txt)
```

## 7.12. Безопасность: запуск от имени root, sudo, и использование `visudo`

- **Никогда не работайте под root постоянно.** Используйте `sudo` только для конкретных команд.
- Чтобы выполнить несколько команд под `sudo`, запустите оболочку: `sudo -i` (но выходите сразу после окончания).
- Редактируйте файлы в `/etc/sudoers` только через `visudo`, чтобы не сломать синтаксис.

**Полезный алиас для безопасности:**
```bash
alias sudo='sudo '   # Позволяет использовать алиасы с sudo (например, sudo ll)
```

## 7.13. Культура написания скриптов (список чек-листов)

Прежде чем отправить скрипт коллегам или положить в продакшн, проверьте себя:

- [ ] **Шебанг** — `#!/bin/bash` или `/usr/bin/env bash`.
- [ ] **Строгий режим** — `set -euo pipefail`.
- [ ] **Обработка аргументов** — проверка количества, вывод справки при `-h` или `--help`.
- [ ] **Логирование** — все ошибки пишутся в stderr (`>&2`), все важные действия — в лог.
- [ ] **Кавычки** — все переменные в двойных кавычках `"$VAR"`.
- [ ] **Временные файлы** — создаются через `mktemp` и удаляются с `trap`.
- [ ] **Пути** — предпочтительно абсолютные или относительные относительно корня скрипта (`$(dirname "$0")`).
- [ ] **Информационные сообщения** — понятны пользователю.
- [ ] **Права** — `chmod 755`.
- [ ] **Документация** — комментарии в начале скрипта с описанием, примерами.

## 7.14. Заключительное напутствие

**Помните главное правило инженера:** *«Ты не должен делать руками то, что может сделать компьютер»*. Если какая-то операция занимает больше 5 минут и вы будете повторять её регулярно — автоматизируйте её. Сначала напишите скрипт для себя, потом предложите его команде.

**Ресурсы для дальнейшего изучения:**
- **Advanced Bash-Scripting Guide** (ABS) — классика.
- **Bash Hackers Wiki** — много примеров и тонкостей.
- **TLDR** — краткие примеры команд.
- **ExplainShell.com** — разбирает сложные пайпы по частям.

**Навыки, которые нужно тренировать каждый день:**
1. Использовать `Ctrl+R` для поиска по истории.
2. Дополнять пути через `Tab`.
3. Писать однострочники с `grep`, `awk`, `sed` вместо поиска вручную.
4. Создавать скрипт, даже если он из 3 строк, для любой повторяющейся задачи.

Через месяц вы заметите, что ваша скорость работы выросла в 2-3 раза. Через год вы будете писать сложные скрипты с закрытыми глазами.

**Финальное домашнее задание (на всю жизнь):**  
Напишите скрипт `env_setup.sh`, который при запуске в новой системе:
- Устанавливает ваши любимые пакеты (`htop`, `tmux`, `git`, `curl` и т.д.).
- Копирует ваш `.bashrc`, `.vimrc`, алиасы с удалённого репозитория.
- Настраивает git (имя, email).
- Проверяет наличие SSH-ключей и генерирует, если их нет.

Этот скрипт будет вашим «паспортом» на любом сервере — вы сможете за минуту настроить окружение под себя.
