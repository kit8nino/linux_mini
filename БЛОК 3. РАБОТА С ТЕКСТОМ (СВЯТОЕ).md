
**Цель блока:** Освоить инструменты обработки потоков данных. Научиться читать логи, вытаскивать из них суть, редактировать конфиги без открытия редактора и комбинировать команды в мощные фильтры.

Философия Linux: «Каждая программа делает что-то одно, но делает это хорошо». Мы не пишем сложный софт, мы соединяем простые утилиты пайпами (`|`).

## 3.1. Просмотр текста: `cat`, `less`, `head`, `tail`

Не открывайте гигабайтные логи в текстовом редакторе — терминал зависнет. Используйте правильные инструменты.

| Команда | Назначение | Ключевой флаг |
| :--- | :--- | :--- |
| **`cat`** | Вывалить ВСЁ содержимое в терминал. Только для **маленьких** файлов (конфиги до 100 строк). | `cat file1 file2 > merged` (склеить файлы). |
| **`less`** | Постраничный просмотр (лучше `more`). Навигация стрелками, `/` для поиска, `q` для выхода. | `less -N` (показывать номера строк). |
| **`head`** | Первые 10 строк (по умолчанию). | `head -n 50` (первые 50 строк). |
| **`tail`** | Последние 10 строк. | `tail -n 20` (последние 20). |

**Святая святых: `tail -f` (follow)**
Это «живой» просмотр логов. Вы запускаете команду, видите новые строки в реальном времени, как только они появляются в файле. Используйте это, когда дебажите работающий сервис.

```bash
tail -f /var/log/nginx/access.log   
# Смотрим, кто стучится на сайт в реальном времени.
```
*Чтобы выйти из `tail -f`, нажмите `Ctrl + C`.*

**Совет для `less`:** Если вы открыли `less` и хотите следить за файлом, как в `tail -f`, нажмите клавишу `F` внутри `less` — он перейдет в режим слежения. Нажмите `Ctrl+C`, чтобы остановить слежение и снова скроллить. Для удобства скролла постранично используйте `Space` или `PgUp` / `PgDwn`.

## 3.2. Поиск и фильтрация: `grep` (меч и молот)

`grep` (Global Regular Expression Print) — самая используемая команда в мире администрирования. Она ищет строки по шаблону.

**Базовый синтаксис:** `grep [флаги] "что_ищем" [файл]`

**Обязательные флаги для повседневного использования:**

| Флаг | Что делает | Когда применять |
| :--- | :--- | :--- |
| `-i` | Игнорирует регистр | `grep -i "error"` найдет ERROR, Error, error. |
| `-n` | Показывает номера строк | `grep -n "function" script.py` — сразу видим, где править. |
| `-v` | Инверсия (показывает ВСЁ, *кроме* совпадений) | `grep -v "DEBUG"` — убрать мусорные дебаг-строки из лога. |
| `-r` или `-R` | Рекурсивный поиск по папке | `grep -r "password" ./` — ищем, не захардкожен ли пароль. |
| `-A N` | After — показать N строк **после** совпадения | `grep -A5 "Exception"` — контекст ошибки. |
| `-B N` | Before — показать N строк **до** совпадения | `grep -B5 "Exception"`. |
| `-C N` | Context — показать N строк **до и после** | `grep -C3 "panic"` — золотой стандарт для логов. |
| `-c` | Посчитать количество совпадений | `grep -c "200 OK" access.log` — сколько успешных запросов. |
| `-o` | Вывести только совпадающую часть (а не всю строку) | `grep -oE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+"` — вытащить все IP-адреса. |
| `-E` | Расширенный регексп (Extended Regex) | Позволяет использовать `+`, `?`, `{}`, `|` (ИЛИ). |

**Боевой пример:** Найти все ошибки с 5 строками контекста во всех логах, игнорируя регистр.
`grep -rin -C5 "fatal" /var/log/`

**Работа с пайпом:** `grep` идеально читает стандартный ввод.
`ps aux | grep nginx | grep -v grep` — найти процесс nginx, но исключить сам процесс `grep` из вывода.

## 3.3. Подсчет строк, слов и байтов: `wc`

Часто нужно узнать, сколько всего записей в логе.

```bash
wc -l access.log   # Выведет количество строк (сколько запросов в логе)
wc -w text.txt     # Количество слов
wc -c binary.bin   # Размер в байтах
```

## 3.4. Сортировка и уникализация: `sort` и `uniq`

Эти две команды всегда работают в паре. `uniq` работает **только** на отсортированных данных.

1.  **`sort`**: Сортирует строки по алфавиту/числам.
    *   `sort -n` — сортировать как числа (а не как строки).
    *   `sort -r` — обратный порядок.
    *   `sort -k 2` — сортировать по второму столбцу.

2.  **`uniq`**: Убирает дубликаты.
    *   `uniq -c` — **Волшебный флаг**. Показывает количество повторений каждой строки.

**Классический пайп для статистики (Анализ логов):**
Вывести топ-10 самых частых IP-адресов из access-лога (где IP стоит первым столбцом):
```bash
cat access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head -10
```
*Разбор:* Вытащили IP -> отсортировали -> посчитали повторы -> отсортировали по убыванию чисел -> взяли топ-10.

## 3.5. Работа со столбцами: `cut` и `awk`

Логи и CSV-файлы обычно имеют структуру. `cut` прост, но `awk` — это целый язык программирования для текста.

**`cut`** — для данных с разделителем (запятая, пробел, табуляция).
*   `cut -d ',' -f 3 file.csv` — разделитель запятая, показать 3-е поле.
*   `cut -d ' ' -f 1 access.log` — показать первый столбец (пробел — разделитель).

**`awk`** — убийца `cut` для сложных случаев.
Синтаксис: `awk '{print $N}'` (где N — номер колонки, `$0` — вся строка).

*   `ps aux | awk '{print $2, $11}'` — показать PID и имя команды.
*   `awk -F ':' '{print $1, $3}' /etc/passwd` — разделитель `:` (двоеточие), вывести логин и UID.
*   **Условия:** `awk '$5 > 1000 {print $1}'` — показать пользователей с UID больше 1000.
*   **Суммирование:** `awk '{sum += $5} END {print sum}'` — подсчитать сумму чисел в 5-й колонке (например, общий трафик).

## 3.6. Редактирование потока: `sed` (Stream EDitor)

`sed` позволяет изменять текст «на лету», не открывая редактор. Это незаменимо для подстановки переменных в конфиги или массовой замены IP-адресов.

**Базовая команда замены:** `s/что_меняем/на_что_меняем/флаги`
*   `g` (global) — заменить все совпадения в строке (без него только первое).

**Примеры:**
1.  Заменить в файле `config.conf` все `127.0.0.1` на `0.0.0.0`:
    `sed -i 's/127.0.0.1/0.0.0.0/g' config.conf` (**`-i`** — редактирование файла на месте! Осторожно).
2.  Сделать бэкап перед заменой (безопасный режим):
    `sed -i.bak 's/old/new/g' config.conf` (создаст config.conf.bak).
3.  Удалить строки, содержащие слово "DEBUG":
    `sed '/DEBUG/d' app.log > clean.log` (без `-i`, выведет в новый файл).
4.  Заменить только во 2-й строке файла:
    `sed -i '2s/true/false/' settings.ini`.

## 3.7. Работа со сжатыми логами: `zcat`, `zgrep`

Логи часто лежат в архивах `access.log.1.gz`. Их не нужно распаковывать!
*   `zcat access.log.1.gz` — показать содержимое архива.
*   `zgrep "ERROR" access.log.1.gz` — поискать ошибку прямо в архиве.

## 3.8. Форматирование сложных данных: `jq` (JSON)

Современные API и микросервисы отдают JSON. Просто так читать его в терминале — боль. Установите `jq` (`apt install jq`).

```bash
curl -s https://api.example.com/users | jq '.'
```
(Красиво подсветит структуру).

*   `jq '.name'` — вытащить поле name.
*   `jq '.[] | .email'` — вытащить все email из массива.

## 3.9. Боевые шаблоны (пайпы, которые спасут жизнь)

Не учите команды — учите шаблоны:

| Задача                                                                       | Команда                                                                                              |
| :--------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------- |
| **Найти папку по имени, в которой есть текст "admin"**                       | `find / -type d -name "admin" 2>/dev/null` (ошибки ушли в /dev/null)                                 |
| **Показать 5 последних ошибок в системном логе**                             | `journalctl -xe `\|` grep -i error `\|` tail -5` (или `tail -50 /var/log/syslog `\|` grep -i error`) |
| **Проверить, кто из пользователей заходит по SSH сегодня**                   | `grep "Accepted" /var/log/auth.log `\|` awk '{print $11}' `\|` sort `\|` uniq -c`                    |
| **Заменить все вхождения URL в конфигах и сохранить**                        | `find ./configs/ -type f -name "*.conf" -exec sed -i 's/http:/https:/g' {} \;`                       |
| **Посчитать общее количество времени выполнения скрипта (сумма по колонке)** | `cat timing.log `\|` awk '{sum+=$3} END {print sum/60 " minutes"}'`                                  |
| **Убрать пустые строки из файла**                                            | `sed '/^$/d' file.txt > new_file.txt`                                                                |

---

**Советы мастерства (Best Practices):**

1.  **Проверяйте на малом куске**: Если собираетесь запустить сложную замену `sed` на 1000 файлов, сначала проверьте на одном: `sed 's/old/new/g' test.txt`.
2.  **Избегайте `cat` в начале пайпа**: Плохо: `cat file | grep text`. Хорошо: `grep text file.` Убирайте лишний процесс.
3.  **Экранирование спецсимволов**: Ищете точку или слеш? Используйте обратный слеш `\`.
    *   Найти IP: `grep "192\.168\."` (ищем буквально "192.168.").
    *   Ищем строку с $: `sed 's/\$VERSION/1.0/g'` (экранируем доллар).
