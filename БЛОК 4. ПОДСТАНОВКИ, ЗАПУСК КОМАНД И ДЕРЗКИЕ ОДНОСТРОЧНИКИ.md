
**Цель блока:** Научиться использовать все виды подстановок, чтобы гибко оперировать данными и командами; понимать разницу в способах запуска процессов; писать компактные, но читаемые цепочки команд, которые решают повседневные задачи в одну строку.

## 4.1. Виды подстановок (Substitution)

Подстановка — это механизм, при котором Bash заменяет часть команды на результат вычисления, значение переменной или сгенерированный список. Это основа динамических команд.

### 4.1.1. Командная подстановка — `$(command)` и обратные кавычки

**Использование:** выполнить команду и подставить её вывод вместо конструкции.

- **Современный синтаксис:** `$(command)` — вложенный, читаемый, легко экранируется.
- **Устаревший синтаксис:** `` `command` `` — сложно вкладывать, проблемы с экранированием.

```bash
# Пример: положить текущую дату в переменную
today=$(date +%Y-%m-%d)
echo "Сегодня $today"

# Вложенная подстановка – легко:
files_count=$(ls -1 | wc -l)
echo "Файлов: $files_count"

# С вложенными кавычками – `$()` спасает:
echo "Текущий пользователь: $(whoami), его дом: $(echo ~)"
```

### 4.1.2. Арифметическая подстановка — `$((выражение))`

Позволяет выполнять целочисленные вычисления. Пробелы внутри не обязательны, но для читаемости ставьте.

```bash
x=5
y=3
sum=$((x + y))
mul=$((x * y))
echo "Сумма: $sum, Произведение: $mul"

# Инкремент переменной:
((x++))
echo "x теперь $x"

# Деление целочисленное:
echo "10 / 3 = $((10 / 3))"  # Выведет 3 (остаток отбрасывается)
```

### 4.1.3. Подстановка переменных — `${VAR}` и её модификаторы

Простое использование: `$VAR` или `${VAR}`. Фигурные скобки обязательны, если переменная сливается с текстом.

```bash
prefix="file"
echo "${prefix}_001.txt"   # file_001.txt (без скобок было бы "$prefix_001" – неверно)
```

**Полезные модификаторы:**

| Конструкция            | Действие                                           | Пример                                                             |
| :--------------------- | :------------------------------------------------- | :----------------------------------------------------------------- |
| `${VAR:-слово}`        | Если VAR не задана или пуста – подставить `слово`  | `name=""` → `echo "${name:-гость}"` → `гость`                      |
| `${VAR:=слово}`        | Если VAR пуста – присвоить ей `слово` и подставить | `unset log` → `echo "${log:=/tmp/log}"` → теперь `log=/tmp/log`    |
| `${VAR/старое/новое}`  | Заменить **первое** вхождение `старое` на `новое`  | `path="/home/user/file"` → `${path/user/root}` → `/home/root/file` |
| `${VAR//старое/новое}` | Заменить **все** вхождения                         | `text="a b a"` → `${text//a/x}` → `x b x`                          |
| `${VAR#префикс}`       | Удалить **кратчайший** префикс                     | `file="project/src/main.c"` → `${file#*/}` → `src/main.c`          |
| `${VAR##префикс}`      | Удалить **длиннейший** префикс                     | `file="project/src/main.c"` → `${file##*/}` → `main.c`             |
| `${VAR%суффикс}`       | Удалить **кратчайший** суффикс                     | `file="main.c.bak"` → `${file%.*}` → `main.c`                      |
| `${VAR%%суффикс}`      | Удалить **длиннейший** суффикс                     | `file="main.c.bak"` → `${file%%.*}` → `main`                       |
| `${#VAR}`              | Длина строки                                       | `str="hello"` → `${#str}` → `5`                                    |

**Примеры из жизни:**
- Переименовать все `.jpg` в `.jpeg`:  
  `for f in *.jpg; do mv "$f" "${f%.jpg}.jpeg"; done`
- Извлечь имя файла из полного пути:  
  `filename=$(basename "$fullpath")` — но можно и через `##*/`.
- Убрать расширение:  
  `basename_noext="${filename%.*}"`

### 4.1.4. Brace expansion — `{a,b,c}` и `{1..10}`

Генерирует списки строк. Работает **до** подстановки переменных, поэтому не используйте с переменными внутри.

```bash
# Создать несколько файлов
touch file_{1..5}.txt         # file_1.txt … file_5.txt

# Создать папки с годами
mkdir -p project/{2023,2024,2025}/src

# Комбинации
echo {a,b}{1,2}   # a1 a2 b1 b2
```

### 4.1.5. Wildcards (глоббинг) — `*`, `?`, `[abc]`

Это не подстановка Bash, а раскрытие имён файлов оболочкой.

- `*` — любое количество любых символов.
- `?` — один любой символ.
- `[abc]` — один из перечисленных символов.
- `[!abc]` — любой, кроме перечисленных.

```bash
ls *.log          # все .log файлы
rm -f file?.txt   # file1.txt, fileA.txt, но не file10.txt
```

### 4.1.6. Tilde expansion — `~` и `~user`

Заменяется на домашнюю папку текущего или указанного пользователя.

```bash
cd ~/projects          # /home/username/projects
ls ~root               # список файлов в /root (если есть права)
```

### 4.1.7. Подстановка процесса — `<(command)` и `>(command)`

Это одна из самых мощных и часто непонятных фич. Она создаёт **временный именованный канал** или файл, который можно передать команде, ожидающей путь к файлу. Вывод команды внутри `<( )` становится доступен как файл.

**Зачем это нужно?** Многие утилиты (например, `diff`, `comm`, `paste`) принимают на вход имена файлов, а не потоки. С помощью подстановки процесса мы можем передать им вывод других команд без создания временных файлов.

```bash
# Сравнить списки файлов в двух папках
diff <(ls /home/user1) <(ls /home/user2)
# Это эквивалентно:
# ls /home/user1 > /tmp/tmp1; ls /home/user2 > /tmp/tmp2; diff /tmp/tmp1 /tmp/tmp2

# Найти строки, которые есть в файле A, но нет в B
comm -23 <(sort fileA) <(sort fileB)

# Передать вывод grep как файл для обработки
wc -l <(grep -r "ERROR" /var/log/)
```

`>(command)` — обратная подстановка: пишет в файл, который перенаправляется на ввод команды. Используется реже.

```bash
# Пример: записать вывод команды в архив на лету
tar -czf >(ssh user@host "cat > backup.tar.gz") ./data
```

**Важно:** подстановка процесса работает только в Bash, не в POSIX-совместимых оболочках (sh).
Кратко как это делать в других оболочках:
- **rc и его производные** (например, `es`): Поддерживают подстановку, но с другим синтаксисом: `<{command}` и `>{command}`[](https://unix.stackexchange.com/revisions/e2b0b58f-b5b6-4052-9857-289c7e710113/view-source).
- **yash**: Имеет собственную реализацию, где `<(...)` используется для "перенаправления процесса", а не для подстановки

| Оболочка            | Поддержка | Синтаксис / Способ                  | Примечание                                       |
| ------------------- | --------- | ----------------------------------- | ------------------------------------------------ |
| **Bash**            | ✅ Да      | `<(...)` , `>(...)`                 | Стандарт де-факто.                               |
| **POSIX sh (dash)** | ❌ Нет     | Используйте `mktemp`, FIFO или пайп | Следует строгому стандарту POSIX.                |
| **Zsh**             | ✅ Да      | `<(...)` , `>(...)` , **`=(...)`**  | `=(...)` создает временный **файл**, а не канал. |
| **Ksh**             | ✅ Да      | `<(...)` , `>(...)`                 | Родоначальник синтаксиса.                        |
| **Fish**            | ✅ Да      | `(command `\|` psub)`               | Использует встроенную функцию `psub`.            |

### 4.1.4. "Здесь-строки" (`<<<`) и "здесь-документы" (`<<`)

Это не совсем подстановка, но способ передать строку как стандартный ввод.

- `<<< "строка"` — передаёт строку как ввод для команды (одна строка).
- `<< DELIMITER` — многострочный ввод до встречи разделителя.

```bash
# Здесь-строка
grep error <<< "this line has an error"   # найдёт "error"

# Здесь-документ (создать файл)
# многострочный ввод (EOF — метка)
cat << EOF > config.txt
user=admin
password=secret
EOF
```

## 4.2. Способы запуска команд

Понимание того, как запускается процесс, критично для контроля над системой. Рассмотрим все основные варианты.

|Способ|Синтаксис|Пояснение|Когда использовать|
|---|---|---|---|
|**Синхронный** (передний план)|`command`|Терминал блокируется до завершения.|Большинство команд.|
|**Фоновый**|`command &`|Команда выполняется параллельно, терминал свободен. Можно управлять через `jobs`, `fg`, `bg`.|Долгие задачи, которые не требуют ввода.|
|**Конвейер** (pipe)|`cmd1 \| cmd2`|STDOUT cmd1 подаётся на STDIN cmd2.|Цепочки обработки данных.|
|**Логическое И**|`cmd1 && cmd2`|cmd2 выполняется **только** если cmd1 завершился с кодом 0 (успех).|Проверки и последовательности, зависящие от успеха.|
|**Логическое ИЛИ**|`cmd1 \| cmd2`|cmd2 выполняется **только** если cmd1 завершился ошибкой (код ≠ 0).|Запасные действия при сбое.|
|**Последовательное выполнение**|`cmd1 ; cmd2`|Выполняется cmd1, затем cmd2, независимо от кода возврата.|Просто последовательность команд.|
|**Игнорирование SIGHUP (nohup)**|`nohup command &`|Запускает команду, игнорируя сигнал `SIGHUP` (закрытие терминала). Вывод по умолчанию перенаправляется в `nohup.out`.|Долгие задачи, которые должны жить после выхода из SSH.|
|**Выполнение в текущей оболочке**|`source script.sh` или `. script.sh`|Скрипт выполняется в текущем процессе, все переменные и изменения каталога сохраняются после выполнения.|Когда нужно изменить окружение текущей сессии (экспорт переменных, смена каталога).|
|**Динамическое выполнение (eval)**|`eval "строка"`|Выполняет строку как команду в текущей оболочке. Это позволяет создавать команды динамически, но **опасно**, так как может привести к выполнению произвольного кода.|Почти никогда не используйте, если не уверены.|
|**Замена текущего процесса (exec)**|`exec command`|Заменяет текущий процесс (оболочку) на новую команду. После выполнения `exec` управление не возвращается в исходную оболочку.|Обычно используется для замены оболочки на другую (например, `exec bash --norc`) или в сценариях, чтобы запустить демона.|
|**Мультиплексор (screen/tmux)**|`tmux new -s mysession`|Создаёт сессию, которая живёт независимо от SSH-соединения.|Для любых долгих задач, требующих интерактивного управления или сохранения вывода.|
|**По расписанию (cron)**|`crontab -e`|Команды выполняются в фоне по расписанию, окружение сильно ограничено.|Автоматизация регулярных задач.|

**Важные нюансы:**

- **`&` vs `nohup`:** `command &` всё ещё умрёт, если терминал закроется (`SIGHUP`). `nohup` делает процесс неубиваемым этим сигналом, но не демонизирует его полностью.
- **`source` vs `./script.sh`:** `./script.sh` запускает скрипт в **дочерней** оболочке — переменные не сохраняются. `source` — в текущей, поэтому изменения остаются.
- **`eval`** часто используют для команд, построенных из переменных. Старайтесь избегать, используйте массивы или функции.
- **`exec`** обычно применяется в конце скрипта для замены на другую программу (например, `exec ssh-agent bash`). Если вы ошибётесь, сессия закроется.

## 4.3. Принципы написания «дерзких однострочников»

Однострочник — это цепочка команд, объединённых пайпами, подстановками и логическими операторами, которая решает задачу без отдельного скрипта. Это искусство, но оно требует дисциплины.

### Основные принципы (с примерами):

**1. Избегайте «бесполезного cat» (UUOC)**

- Плохо: `cat file | grep pattern`
- Хорошо: `grep pattern file`

Это экономит один процесс и ускоряет работу с большими файлами.

**2. Используйте короткие флаги, но не в ущерб читаемости**

- `grep -rni` лучше, чем `grep --recursive --ignore-case --line-number`, если вы помните их значение.

**3. Комбинируйте утилиты по их сильным сторонам**

- `grep` — фильтрация строк.
- `sed` — замена текста.
- `awk` — работа с колонками и агрегация.
- `sort` / `uniq` — сортировка и подсчёт уникальных.
- `cut` — простое вырезание полей.

**4. Используйте арифметические и командные подстановки внутри пайпов**

```bash
# Увеличить значение в файле на 1 и записать обратно
echo $(( $(cat count.txt) + 1 )) > count.txt
```

**5. Используйте `xargs` для массовых операций, но осторожно с пробелами**

- Безопасный способ: `find . -name "*.tmp" -print0 | xargs -0 rm -f`
- `-print0` и `-0` гарантируют правильную обработку имён с пробелами.

**6. Используйте здесь-строки (`<<<`) для короткого ввода**

- Вместо `echo "5+3" | bc` пишите `bc <<< "5+3"`.

**7. Используйте логические операторы `&&` и `||` для кратких условий**

```bash
ping -c1 google.com &>/dev/null && echo "Интернет есть" || echo "Нет интернета"
```

**4. Подстановка процесса (`<()`) — мощный приём для сравнения данных**

```bash
diff <(sort file1) <(sort file2)
```

**9. Используйте `find -exec` с `+` для пакетной обработки (быстрее, чем `-exec \;`)**

```bash
find . -name "*.log" -exec grep -l "ERROR" {} +
```

**10. Если однострочник становится длиннее 80 символов или содержит >3 пайпов — лучше вынести в скрипт**

- Добавьте комментарии, проверку ошибок, логирование. Это сэкономит время при повторном использовании.

**11. Всегда проверяйте опасные команды через сухой запуск (`dry-run`)**

```bash
# Показать, что будет удалено:
find /tmp -name "*.tmp" -print
# Убедившись, замените -print на -delete
```

**12. Экранируйте спецсимволы в `sed` и `grep`**

- Для точки: `\.`, для слеша: `\/`, для звёздочки: `\*`.
- Используйте другой разделитель в `sed`, чтобы избежать лесенки: `sed 's#old/path#new/path#g'`.

## 4.4. Разбор классических однострочников (с комментариями)

### 1. Топ-10 IP-адресов из access-лога
```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -10
```
- `awk '{print $1}'` — берёт первый столбец (IP).
- `sort` — группирует одинаковые.
- `uniq -c` — считает повторы.
- `sort -nr` — сортирует по убыванию числа.
- `head -10` — оставляет топ-10.

### 2. Замена строки во всех .conf файлах с созданием бэкапа
```bash
find /etc -name "*.conf" -exec sed -i.bak 's/127.0.0.1/0.0.0.0/g' {} \;
```
- `find /etc -name "*.conf"` — находит все .conf.
- `-exec sed -i.bak` — выполняет `sed` с созданием бэкапа.
- `s/127\.0\.0\.1/0\.0\.0\.0/g` — глобальная замена IP (точки экранированы).
- `{}` — подставляется имя файла.
- `\;` — завершает `-exec`.

### 3. Быстрая проверка, жив ли сервис, и его запуск
```bash
pgrep -x nginx || sudo systemctl start nginx
```
- `pgrep -x` — ищет точное совпадение имени процесса.
- `||` — если `pgrep` не нашёл (код ≠ 0), выполняется запуск.

### 4. Переименование расширений в папке
```bash
for f in *.htm; do mv "$f" "${f%.htm}.html"; done
```
- `for f in *.htm` — перебирает все .htm файлы.
- `mv "$f" "${f%.htm}.html"` — заменяет суффикс.
- `${f%.htm}` — удаляет `.htm` с конца.

### 5. Сравнение двух удалённых файлов (без копирования)
```bash
diff <(ssh user@host1 'cat /etc/hosts') <(ssh user@host2 'cat /etc/hosts')
```
- Подстановка процесса создаёт временные файлы из вывода `ssh`.
- `diff` сравнивает их.

### 6. Подсчёт строк кода в проекте (исключая пустые и комментарии)
```bash
find . -name "*.py" -exec cat {} \; | grep -v '^$' | grep -v '^#' | wc -l
```
- `find . -name "*.py" -exec cat {} \;` — выводит содержимое всех .py.
- `grep -v '^$'` — удаляет пустые строки.
- `grep -v '^#'` — удаляет строки, начинающиеся с `#`.
- `wc -l` — считает строки.

## 4.5. Когда однострочник превращается в скрипт?

Если вы:
- используете однострочник более трёх раз;
- передаёте его коллегам или используете в продакшене;
- планируете запускать по cron;
- он содержит сложную логику (циклы, условия, несколько этапов);

то **превратите его в скрипт**. Добавьте:
- `#!/bin/bash` и `set -euo pipefail`;
- комментарии, поясняющие шаги;
- обработку ошибок и логирование;
- проверку аргументов (если нужны).

Это сэкономит время в будущем и облегчит поддержку.

## 4.6. Заключительные советы

- Практикуйтесь в написании однострочников, решая небольшие задачи (например, найти 10 самых больших файлов, подсчитать количество вхождений слова в логах).
- Не бойтесь экспериментировать, но всегда делайте бэкапы данных перед опасными операциями.
- Помните: читаемость кода важнее, чем его краткость. Если через неделю вы не поймёте свой однострочник — он плох.
