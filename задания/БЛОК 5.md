## Задание 1. Что такое процесс и PID (5.1)

1. Запустите долгую команду и посмотрите её PID:
   ```bash
   sleep 300 &
   echo "PID фонового sleep: $!"
   ```
2. Узнайте PID текущей оболочки:
   ```bash
   echo "PID текущего Bash: $$"
   echo "PPID текущего Bash: $PPID"
   ```
3. Посмотрите иерархию от вашей оболочки:
   ```bash
   ps -o pid,ppid,comm -p $$
   ps -o pid,ppid,comm -p $PPID
   ```
4. Найдите PID 1:
   ```bash
   ps -p 1 -o pid,ppid,comm,args
   ```
5. Убедитесь, что все процессы имеют родителя:
   ```bash
   ps -eo pid,ppid,comm | head -15
   ```

**Проверка:** объясните разницу между программой, процессом, PID и PPID.

## Задание 2. Статические снимки: `ps` (5.2)

1. Посмотрите все процессы в стиле BSD:
   ```bash
   ps aux | head -15
   ```
2. Посмотрите все процессы в стиле System V:
   ```bash
   ps -ef | head -15
   ```
3. Найдите конкретный процесс:
   ```bash
   ps aux | grep -v grep | grep bash
   ps -ef | grep -v grep | grep bash
   ```
4. Посмотрите дерево процессов:
   ```bash
   ps auxf | head -30
   ```
5. Выведите только нужные колонки:
   ```bash
   ps -eo pid,ppid,user,%cpu,%mem,stat,comm --sort=-%cpu | head -10
   ps -eo pid,ppid,user,%cpu,%mem,stat,comm --sort=-%mem | head -10
   ```
6. Найдите свой процесс `sleep`:
   ```bash
   ps -eo pid,ppid,stat,comm,args | grep -v grep | grep sleep
   ```

**Проверка:** уметь читать колонки `ps aux`, находить PPID и сортировать по CPU/RAM.

## Задание 3. Статусы процессов: `STAT` (5.3)

1. Запустите несколько процессов в разных состояниях:
   ```bash
   sleep 300 &                       # фоновый (S)
   yes > /dev/null &                 # активный (R)
   sleep 60                          # нажмите Ctrl+Z (T)
   ```
2. Посмотрите их статусы:
   ```bash
   ps -eo pid,stat,comm | grep -E "sleep|yes"
   ```
3. Приостановите и возобновите процесс:
   ```bash
   jobs
   bg %1        # возобновить в фоне
   fg %1        # вернуть на передний план (Ctrl+C для выхода)
   ```
4. Найдите процесс в статусе `Z` (если есть) или объясните, как он появляется:
   ```bash
   ps -eo pid,ppid,stat,comm | awk '$3 ~ /Z/'
   ```
5. Найдите процессы в статусе `D` (обычно нет, но проверьте):
   ```bash
   ps -eo pid,stat,comm | awk '$2 ~ /D/'
   ```
6. Уберите за собой:
   ```bash
   kill %1 %2 2>/dev/null
   jobs
   ```

**Проверка:** уметь объяснить `R`, `S`, `D`, `Z`, `T`.

## Задание 4. Интерактивный мониторинг: `top` и `htop` (5.4)

1. Запустите `top`:
   ```bash
   top
   ```
   Внутри:
   - Нажмите `P` (сортировка по CPU).
   - Нажмите `M` (сортировка по памяти).
   - Нажмите `1` (показать все ядра CPU).
   - Нажмите `q` (выход).
2. Установите `htop`, если его нет:
   ```bash
   sudo apt install htop   # или sudo yum install htop
   ```
3. Запустите `htop`:
   ```bash
   htop
   ```
   Внутри:
   - `F5` — дерево процессов.
   - `F6` — сортировка (выберите CPU%).
   - `F9` — отправка сигнала.
   - `F10` — выход.
4. Сравните `top` и `htop`:
   - Какие процессы видны в обоих?
   - Где удобнее?

**Проверка:** уметь отсортировать по CPU/RAM и найти «жирный» процесс.

## Задание 5. Сигналы: `kill`, `killall`, `pkill` (5.5)

1. Посмотрите список сигналов:
   ```bash
   kill -l | head -20
   ```
2. Запустите тестовый процесс:
   ```bash
   sleep 600 &
   SLEEP_PID=$!
   echo "PID: $SLEEP_PID"
   ```
3. Отправьте `SIGTERM` (15):
   ```bash
   kill -15 $SLEEP_PID
   sleep 1
   ps -p $SLEEP_PID
   ```
4. Запустите ещё один и убейте `SIGKILL` (9):
   ```bash
   sleep 600 &
   SLEEP_PID=$!
   kill -9 $SLEEP_PID
   sleep 1
   ps -p $SLEEP_PID
   ```
5. Массовое убийство по имени:
   ```bash
   sleep 600 &
   sleep 600 &
   killall sleep
   sleep 1
   pgrep -a sleep
   ```
6. Убийство по части командной строки:
   ```bash
   sleep 600 --fake-arg &
   pkill -f "fake-arg"
   sleep 1
   pgrep -af "fake-arg"
   ```
7. Проверьте `SIGHUP` (только для сервисов, не для системных):
   ```bash
   # Не запускайте на реальных сервисах без необходимости!
   # Пример: kill -1 $(pgrep -x nginx | head -1)
   echo "SIGHUP перечитывает конфиг (пример для nginx)"
   ```

**Проверка:** объяснить разницу между 15, 9 и 1, и когда какой использовать.

## Задание 6. Приоритеты: `nice` и `renice` (5.6)

1. Посмотрите текущий nice-уровень процессов:
   ```bash
   ps -eo pid,ni,comm | head -10
   ```
2. Запустите процесс с низким приоритетом:
   ```bash
   nice -n 10 sleep 300 &
   NICE_PID=$!
   ps -o pid,ni,comm -p $NICE_PID
   ```
3. Измените приоритет работающего процесса:
   ```bash
   renice -n 5 -p $NICE_PID
   ps -o pid,ni,comm -p $NICE_PID
   ```
4. Попробуйте поднять приоритет (может потребовать `sudo`):
   ```bash
   sudo renice -n -5 -p $NICE_PID 2>/dev/null
   ps -o pid,ni,comm -p $NICE_PID
   ```
5. Уберите за собой:
   ```bash
   kill $NICE_PID 2>/dev/null
   ```

**Проверка:** понимать диапазон nice от -20 до +19 и зачем он нужен.

## Задание 7. Фоновые задачи: `&`, `jobs`, `fg`, `bg` (5.7)

## Задание 8. Демоны и SIGHUP: `nohup`, `disown`, `tmux` (5.8)

1. **`nohup`:**
   ```bash
   mkdir -p /tmp/block5 && cd /tmp/block5
   nohup sleep 60 &
   ls -l nohup.out
   cat nohup.out 2>/dev/null
   ```
2. **`disown`** (отвязка от терминала):
   ```bash
   sleep 120 &
   jobs
   disown -h %1
   jobs    # задача исчезнет из списка, но продолжит работать
   pgrep -a sleep
   ```
3. **`tmux`** (если установлен):
   ```bash
   sudo apt install tmux   # если нет
   tmux new -s demo -d
   tmux ls
   tmux send-keys -t demo "sleep 300" Enter
   tmux attach -t demo
   # Внутри: Ctrl+B, затем D — отцепиться
   tmux ls
   tmux kill-session -t demo
   ```
4. **`screen`** (альтернатива):
   ```bash
   sudo apt install screen
   screen -dmS demo2 sleep 300
   screen -ls
   screen -S demo2 -X quit
   ```
5. Уберите за собой:
   ```bash
   pkill -f "sleep 60" 2>/dev/null
   pkill -f "sleep 120" 2>/dev/null
   pkill -f "sleep 300" 2>/dev/null
   ```

**Проверка:** понимать разницу между `&`, `nohup`, `disown`, `tmux` и `screen`.

## Задание 9. Боевые сценарии (5.9)

1. **Найти жирный процесс по CPU:**
   ```bash
   ps -eo pid,ppid,%cpu,%mem,stat,comm --sort=-%cpu | head -5
   ```
2. **Найти жирный процесс по памяти:**
   ```bash
   ps -eo pid,ppid,%cpu,%mem,stat,comm --sort=-%mem | head -5
   ```
3. **Симулировать нагрузку и найти её:**
   ```bash
   yes > /dev/null &
   YES_PID=$!
   ps -eo pid,%cpu,comm --sort=-%cpu | head -3
   kill -15 $YES_PID
   ```
4. **Перечитать конфиг через SIGHUP (на примере своего скрипта):**
   ```bash
   cat > /tmp/block5/reload.sh << 'EOF'
   #!/bin/bash
   trap 'echo "Получен SIGHUP — перечитываю конфиг"' HUP
   while true; do sleep 1; done
   EOF
   chmod +x /tmp/block5/reload.sh
   /tmp/block5/reload.sh &
   RELOAD_PID=$!
   kill -1 $RELOAD_PID
   sleep 1
   kill $RELOAD_PID
   ```
5. **Отвязать долгую задачу от терминала:**
   ```bash
   sleep 180 &
   disown -h %1
   jobs
   pgrep -a sleep
   pkill -f "sleep 180"
   ```

**Проверка:** понимать, как действовать при зависании, перегрузке и долгих задачах.

## Задание 10. Комплексный мини-проект (5.1–5.9)

1. Создайте проект:
   ```bash
   mkdir -p /tmp/block5_project && cd /tmp/block5_project
   ```
2. Запустите три процесса с разными приоритетами:
   ```bash
   nice -n 10 sleep 600 &
   nice -n 5  sleep 600 &
   nice -n 0  sleep 600 &
   jobs
   ```
3. Посмотрите их в `ps` с PPID и nice:
   ```bash
   ps -eo pid,ppid,ni,stat,comm | grep -E "sleep|PID"
   ```
4. Найдите PID каждого и сохраните в файл:
   ```bash
   pgrep -a sleep > pids.txt
   cat pids.txt
   ```
5. Отправьте одному `SIGTERM`, другому `SIGKILL`:
   ```bash
   PID1=$(awk 'NR==1{print $1}' pids.txt)
   PID2=$(awk 'NR==2{print $1}' pids.txt)
   kill -15 $PID1
   kill -9  $PID2
   sleep 1
   pgrep -a sleep
   ```
6. Приостановите оставшийся, затем продолжите в фоне:
   ```bash
   fg %3
   # Ctrl+Z
   bg %3
   jobs
   ```
7. Отвяжите его от терминала:
   ```bash
   disown -h %3
   jobs
   pgrep -a sleep
   ```
8. Убейте всё, что осталось:
   ```bash
   pkill -f "sleep 600"
   pgrep -a sleep
   ```
9. Уберите за собой:
   ```bash
   cd /
   rm -rf /tmp/block5_project /tmp/block5
   ```

**Проверка:** вы объединили `ps`, приоритеты, сигналы, фоновые задачи и `disown`.
