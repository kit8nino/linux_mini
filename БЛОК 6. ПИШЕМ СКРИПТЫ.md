 
**Цель блока:** Научиться создавать исполняемые файлы-скрипты, которые могут принимать аргументы, принимать решения, выполнять повторяющиеся действия и корректно обрабатывать ошибки. Вы должны уметь набросать скрипт для бэкапа, мониторинга или массовой обработки данных за 5-10 минут.

---

## 6.1. Что такое скрипт и зачем он нужен

**Скрипт** — это обычный текстовый файл, в котором записаны команды Bash в том порядке, в котором они должны выполняться. Когда вы запускаете скрипт, Bash читает его построчно и выполняет каждую команду так, как если бы вы вводили её вручную.

**Правило «трёх повторений»:** Если вы выполняете какую-то последовательность команд в третий раз — напишите скрипт. Это сэкономит вам часы в будущем.

---

## 6.2. Первая строка: шебанг (shebang)

Первая строка скрипта всегда указывает, какой интерпретатор должен его выполнять. Это критично, если вы запускаете скрипт из другой оболочки или из cron.

```bash
#!/bin/bash
```
- `#!` — магическая последовательность (shebang).
- `/bin/bash` — путь к интерпретатору (может быть `/bin/sh`, `/usr/bin/python3` и т.д.)

**Важно:** В строке шебанга не должно быть пробелов. Если вы сомневаетесь, где находится bash, выполните `which bash` и вставьте этот путь.

---

## 6.3. Права на выполнение

Текстовый файл с шебангом — ещё не скрипт. Его нужно сделать исполняемым.
```bash
chmod +x my_script.sh
```
Теперь его можно запускать:
- `./my_script.sh` (из текущей папки)
- `/full/path/to/my_script.sh` (абсолютный путь)
- `bash my_script.sh` (запуск через интерпретатор, даже если не выставлены права)

**Стандарт:** Все ваши скрипты должны иметь права `755` (`chmod 755 script.sh`).

## 6.4. Переменные: храним данные

Переменные в Bash не требуют объявления типа. Они могут хранить строки, числа, пути.

**Правила именования:** только латиница, цифры и подчеркивание. Нельзя начинать с цифры.

**Присвоение (без пробелов вокруг `=`!):**
```bash
NAME="Стажер"                # Строка
COUNT=10                     # Число (хранится как строка, но участвует в арифметике)
LOG_FILE="/var/log/my.log"   # Путь
CURRENT_DATE=$(date +%Y%m%d) # Подстановка результата команды
FILES_COUNT=`ls -1 | wc -l`  # Старый стиль (обратные кавычки), лучше использовать $()
```

**Использование (с `$`):**
```bash
echo "Привет, $NAME"         # Выведет: Привет, Стажер
echo "Сегодня: $CURRENT_DATE"
```

**Важнейшее правило:** Всегда заключайте переменные в **двойные кавычки**, если они могут содержать пробелы или спецсимволы.
```bash
# ПЛОХО (сломается, если путь содержит пробелы):
rm -rf $FOLDER

# ХОРОШО:
rm -rf "$FOLDER"
```

**Специальные предопределенные переменные:**

| Переменная      | Значение                                                              |
| :-------------- | :-------------------------------------------------------------------- |
| `$0`            | Имя самого скрипта.                                                   |
| `$1`, `$2`, ... | Аргументы, переданные скрипту (первый, второй и т.д.).                |
| `$#`            | Количество переданных аргументов.                                     |
| `$@`            | Все аргументы как отдельные строки.                                   |
| `$*`            | Все аргументы как одна строка.                                        |
| `$?`            | Код возврата последней выполненной команды (0 — успех, иначе ошибка). |
| `$$`            | PID текущего процесса (самого скрипта).                               |

## 6.5. Арифметика в bash

В bash всё — строки. Чтобы выполнить арифметику, используйте двойные круглые скобки `(( ))` или команду `let`.

```bash
A=5
B=3
SUM=$((A + B))          # Сложение
DIFF=$((A - B))         # Вычитание
MUL=$((A * B))          # Умножение (звездочку экранировать не нужно внутри (()))
DIV=$((A / B))          # Деление (целочисленное, результат = 1)
MOD=$((A % B))          # Остаток от деления (2)

echo "Сумма: $SUM"

# Инкремент (увеличить на 1)
((A++))                 # Теперь A = 6
echo $A

# Сравнение чисел в (( )):
if (( A > B )); then
    echo "A больше B"
fi
```

## 6.6. Условные операторы: `if`, `elif`, `else`

Скрипт должен уметь принимать решения. Условие проверяется командой `test` или конструкцией `[ ]`.

**Синтаксис (обратите внимание на пробелы!):**
```bash
if [ условие ]; then
    # команды, если условие истинно
elif [ другое_условие ]; then
    # команды, если другое условие истинно
else
    # команды, если ни одно условие не истинно
fi
```

**Пробел после `[` и перед `]` — обязателен!**

**Самые частые проверки (флаги):**

| Проверка | Флаг | Пример |
| :--- | :--- | :--- |
| Существует ли файл? | `-f` | `[ -f "/etc/nginx.conf" ]` |
| Существует ли папка? | `-d` | `[ -d "/home/user" ]` |
| Пустая ли строка? | `-z` | `[ -z "$VAR" ]` (true, если VAR пустая) |
| Непустая ли строка? | `-n` | `[ -n "$VAR" ]` |
| Равны ли строки? | `=` | `[ "$VAR1" = "$VAR2" ]` |
| Не равны ли строки? | `!=` | `[ "$VAR1" != "$VAR2" ]` |
| Численное сравнение | `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge` | `[ "$A" -gt "$B" ]` (A > B) |

**Использование двойных квадратных скобок `[[ ]]` (продвинутый режим):**
`[[ ]]` — более мощная и безопасная альтернатива. Внутри не нужно экранировать `<` и `>`, работает `&&` и `||`, поддерживаются регулярные выражения.
```bash
if [[ "$USER" == "root" ]] || [[ "$UID" -eq 0 ]]; then
    echo "Вы — суперпользователь"
fi

if [[ "$FILE" =~ \.txt$ ]]; then
    echo "Это текстовый файл"
fi
```

**Пример: проверка наличия файла перед удалением**
```bash
BACKUP_FILE="/tmp/backup.tar.gz"
if [ -f "$BACKUP_FILE" ]; then
    echo "Внимание: файл бэкапа уже существует. Перезаписать? (y/n)"
    read ANSWER
    if [ "$ANSWER" = "y" ]; then
        rm -f "$BACKUP_FILE"
        echo "Старый файл удален"
    else
        echo "Операция отменена"
        exit 1
    fi
else
    echo "Файл не найден, можно создавать новый"
fi
```

## 6.7. Циклы: автоматизация повторяющихся действий

**Цикл `for` — перебор списка.**
```bash
# Перебор элементов списка
for ITEM in file1 file2 file3; do
    echo "Обрабатываю $ITEM"
done

# Перебор файлов по маске (самый частый сценарий)
for LOG in /var/log/*.log; do
    echo "Архивирую $LOG"
    gzip "$LOG"
done

# Цикл с числовым счетчиком (стиль C)
for ((i=1; i<=10; i++)); do
    echo "Итерация номер $i"
    sleep 1
done
```

**Цикл `while` — выполняется, пока условие истинно.**
Идеален для чтения файлов построчно или бесконечных мониторингов.
```bash
# Чтение файла построчно
while IFS= read -r LINE; do
    echo "Строка: $LINE"
done < "input.txt"

# Бесконечный цикл с прерыванием по условию
while true; do
    DATE=$(date +%H:%M:%S)
    echo "[$DATE] Мониторинг..."
    if pgrep -x "nginx" > /dev/null; then
        echo "Nginx жив"
    else
        echo "Nginx мертв! Перезапуск..."
        systemctl restart nginx
    fi
    sleep 60
done
```

**Цикл `until` — выполняется, пока условие ложно (редко используется).**

## 6.8. Функции: модульность кода

Функции позволяют группировать код, который используется несколько раз. Это делает скрипты читаемыми и переиспользуемыми.

**Объявление:**
```bash
function log_message() {
    local TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
    echo "[$TIMESTAMP] $1" >> /var/log/my_app.log
}
```
- `function` — ключевое слово (можно опустить: `log_message() { ... }`).
- `local` — переменная видна только внутри функции (не засоряет глобальное пространство).
- `$1` — первый аргумент, переданный функции при вызове.

**Вызов:**
```bash
log_message "Скрипт запущен"
# ... какая-то работа ...
log_message "Скрипт завершен успешно"
```

**Возврат значения:**
Функция возвращает числовой код (0 — успех). Чтобы вернуть строку, используйте `echo` и захват через `$()`.
```bash
function get_current_username() {
    echo "$USER"  # Эта строка станет результатом функции
}

USERNAME=$(get_current_username)
echo "Имя пользователя: $USERNAME"
```

## 6.9. Обработка ошибок и безопасность

**Код возврата (`$?`):** Каждая команда возвращает 0 при успехе и любое другое число (1-255) при ошибке. Проверяйте его!
```bash
mkdir /tmp/new_dir
if [ $? -eq 0 ]; then
    echo "Папка создана"
else
    echo "Ошибка создания папки" >&2
    exit 1
fi
```

**Директива `set -e` (авто-выход при ошибке):**
Добавьте в начало скрипта `set -e`. Тогда скрипт прервется, как только любая команда завершится с ненулевым кодом. Спасает от каскадных ошибок.
```bash
#!/bin/bash
set -e          # Выход при любой ошибке
set -u          # Выход при использовании необъявленной переменной
set -o pipefail # Ошибка в пайпе тоже прерывает выполнение

# Теперь если cd в несуществующую папку — скрипт остановится
cd /some/unknown/folder
echo "Эта строка не выполнится"
```

**Ловушка `trap` — выполнить действие при выходе:**
Очистка временных файлов, даже если скрипт упал с ошибкой.
```bash
TEMP_FILE=$(mktemp)
trap 'rm -f "$TEMP_FILE"; echo "Временные файлы удалены"' EXIT

# ... работа с $TEMP_FILE ...
```

## 6.10. Отладка скриптов

Никогда не запускайте сложный скрипт «вслепую».

**Способ 1: Режим трассировки (`bash -x`)**
Запустите скрипт с флагом `-x`, чтобы видеть каждую выполняемую команду с подставленными значениями переменных.
```bash
bash -x my_script.sh
```
Или внутри скрипта включить/выключить:
```bash
set -x   # Включить отладку
echo "Это видно с отладкой"
set +x   # Выключить отладку
```

**Способ 2: Проверка синтаксиса без выполнения**
```bash
bash -n my_script.sh
```
Эта команда проверит синтаксис (закрыты ли скобки, кавычки) и ничего не выполнит.

## 6.11. Боевые шаблоны (скопируйте и используйте)

**Шаблон 1: Бэкап папки с ротацией**
```bash
#!/bin/bash
set -e
SOURCE="/home/user/project"
BACKUP_DIR="/backups"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/project_$DATE.tar.gz"

if [ ! -d "$SOURCE" ]; then
    echo "Ошибка: исходная папка не существует" >&2
    exit 1
fi

tar -czf "$BACKUP_FILE" "$SOURCE"
echo "Бэкап создан: $BACKUP_FILE"

# Удалить бэкапы старше 30 дней
find "$BACKUP_DIR" -name "project_*.tar.gz" -mtime +30 -delete
```

**Шаблон 2: Ожидание доступности сервиса**
```bash
#!/bin/bash
HOST="google.com"
PORT=80
TIMEOUT=30

echo "Ожидаем доступность $HOST:$PORT..."
for ((i=1; i<=TIMEOUT; i++)); do
    if nc -z "$HOST" "$PORT" 2>/dev/null; then
        echo "Сервис доступен!"
        exit 0
    fi
    sleep 1
    echo -n "."
done
echo "Таймаут! Сервис недоступен"
exit 1
```

**Шаблон 3: Массовое переименование файлов**
```bash
#!/bin/bash
# Переименовать все .JPG в .jpg (привести к нижнему регистру)
for FILE in *.JPG; do
    NEWNAME=$(echo "$FILE" | tr '[:upper:]' '[:lower:]')
    mv "$FILE" "$NEWNAME"
    echo "$FILE -> $NEWNAME"
done
```

**Шаблон 4: Парсинг JSON через `jq`**
```bash
#!/bin/bash
API_URL="https://api.github.com/repos/kubernetes/kubernetes/releases/latest"
VERSION=$(curl -s "$API_URL" | jq -r '.tag_name')

```

#### [Как писать bash-скрипты надежно и безопасно: минимальный шаблон](https://habr.com/ru/articles/590021/)

Если нужен скрипт, который делает много всего и должен выполнять это надежно, наглядно и красиво, то полезно взять универсальный шаблон. Их довольно много разных, как сложных, так и более компактных. Ниже один из сбалансированных вариантов, который отлично может быть использован как стартовая точка (его подробный разбор в статье по ссылке в заголовке).

```bash
#!/usr/bin/env bash

set -Eeuo pipefail
trap cleanup SIGINT SIGTERM ERR EXIT

script_dir=$(cd "$(dirname "${BASH_SOURCE[0]}")" &>/dev/null && pwd -P)

usage() {
  cat <<EOF
Usage: $(basename "${BASH_SOURCE[0]}") [-h] [-v] [-f] -p param_value arg1 [arg2...]

Script description here.

Available options:

-h, --help      Print this help and exit
-v, --verbose   Print script debug info
-f, --flag      Some flag description
-p, --param     Some param description
EOF
  exit
}

cleanup() {
  trap - SIGINT SIGTERM ERR EXIT
  # script cleanup here
}

setup_colors() {
  if [[ -t 2 ]] && [[ -z "${NO_COLOR-}" ]] && [[ "${TERM-}" != "dumb" ]]; then
    NOFORMAT='\033[0m' RED='\033[0;31m' GREEN='\033[0;32m' ORANGE='\033[0;33m' BLUE='\033[0;34m' PURPLE='\033[0;35m' CYAN='\033[0;36m' YELLOW='\033[1;33m'
  else
    NOFORMAT='' RED='' GREEN='' ORANGE='' BLUE='' PURPLE='' CYAN='' YELLOW=''
  fi
}

msg() {
  echo >&2 -e "${1-}"
}

die() {
  local msg=$1
  local code=${2-1} # default exit status 1
  msg "$msg"
  exit "$code"
}

parse_params() {
  # default values of variables set from params
  flag=0
  param=''

  while :; do
    case "${1-}" in
    -h | --help) usage ;;
    -v | --verbose) set -x ;;
    --no-color) NO_COLOR=1 ;;
    -f | --flag) flag=1 ;; # example flag
    -p | --param) # example named parameter
      param="${2-}"
      shift
      ;;
    -?*) die "Unknown option: $1" ;;
    *) break ;;
    esac
    shift
  done

  args=("$@")

  # check required params and arguments
  [[ -z "${param-}" ]] && die "Missing required parameter: param"
  [[ ${#args[@]} -eq 0 ]] && die "Missing script arguments"

  return 0
}

parse_params "$@"
setup_colors

# script logic here

msg "${RED}Read parameters:${NOFORMAT}"
msg "- flag: ${flag}"
msg "- param: ${param}"
msg "- arguments: ${args[*]-}"

```

## 6.12. Cron: автоматический запуск скриптов по расписанию

Ваши скрипты бесполезны, если их не запускать автоматически.
- Редактировать расписание текущего пользователя: `crontab -e`
- Формат строки: `минута час день_месяца месяц день_недели команда`

**Примеры:**
```bash
# Каждую минуту
* * * * * /home/user/monitor.sh >> /var/log/monitor.log 2>&1

# Каждый час в 15 минут
15 * * * * /home/user/backup.sh

# Каждый день в 3 часа ночи
0 3 * * * /home/user/daily_cleanup.sh

# Каждое воскресенье в 5 утра
0 5 * * 0 /home/user/weekly_report.sh
```

**Важно:** В cron окружение минимальное (нет ваших `PATH` и переменных). Всегда используйте **абсолютные пути** к командам и файлам в скриптах, запускаемых из cron.

## 6.13. Лучшие практики (свод правил)

1. **Всегда начинайте скрипт с `#!/bin/bash` и `set -euo pipefail`.**
2. **Заключайте переменные в кавычки:** `"$VAR"`.
3. **Используйте `$(...)` вместо обратных кавычек.**
4. **Проверяйте количество аргументов**, если скрипт их принимает:
   ```bash
   if [ $# -ne 2 ]; then
       echo "Использование: $0 <входной_файл> <выходной_файл>" >&2
       exit 1
   fi
   ```
5. **Пишите понятные сообщения об ошибках** и направляйте их в `>&2` (stderr).
6. **Не используйте `exit` без кода**, если не уверены — всегда указывайте `exit 0` для успеха или `exit 1` для ошибки.
7. **Документируйте скрипты** — добавьте комментарии в начале с описанием, автором, примерами использования.
8. **Тестируйте на небольших данных:** перед тем как запустить `find ... -delete`, сначала выполните ту же команду без `-delete` и посмотрите, что найдется.

**Задание для самопроверки к Блоку 6:**

Напиши скрипт `deploy.sh`, который делает следующее:
1. Принимает два аргумента: имя проекта (например, `myapp`) и версию (например, `v1.2.3`).
2. Создает папку `/var/www/<имя_проекта>/<версия>/`.
3. Копирует в неё все файлы из текущей папки (где лежит скрипт), исключая файлы `.log` и `.tmp`.
4. Создает символическую ссылку `/var/www/<имя_проекта>/current`, указывающую на только что созданную папку с версией.
5. Записывает в лог-файл `/var/log/deploy.log` время, имя проекта, версию и результат операции (успех/ошибка).
6. Проверяет, что передан ровно 2 аргумента, иначе выводит подсказку и завершается с кодом ошибки.
7. Использует функции для логирования.
8. В конце выводит сообщение: "Деплой завершен. Текущая версия: <версия>".

**Проверка:** запусти скрипт с `bash -x deploy.sh myapp v1.0`, затем проверь, что папка создана, ссылка появилась, и в логе есть запись.
