## 1.1. Слоеный пирог: Железо → Ядро → Оболочка

Ваш компьютер/сервер — это железо (процессор, память, диски). С ним напрямую работать сложно, поэтому есть **Ядро (Kernel)**.

*   **Ядро** — это программа №1. Она загружается самой первой и управляет всеми процессами, памятью и драйверами устройств. Это «диспетчер», который решает, кому сколько ресурсов дать.
*   **Оболочка (Shell)** — это программа, которая запускается поверх ядра (для пользователя). Она принимает ваш ввод с клавиатуры, переводит его на язык, понятный ядру, и показывает результат.

**Bash (Bourne Again SHell)** — самая популярная оболочка в Linux. **Запомните:** Bash — это такой же обычный процесс, как ваш браузер или калькулятор. Когда вы открываете терминал, вы внутри Bash. Когда вы пишете скрипт, вы просто записываете список команд, которые Bash должен выполнить по очереди.

## 1.2. «Всё есть файл» — Главная философия

В Windows диск C: и флешка — это разные устройства. В Linux **абсолютно всё** представлено в виде файлов в единой корневой папке `/`.

Это не просто слова, это правило, по которому вы будете чинить системы:

1.  **Обычные данные** (`/home/user/text.txt`, `/etc/nginx.conf`) — просто текстовые файлы.
2.  **Диски и флешки** — тоже файлы в папке `/dev/` (например, `sda` — ваш первый жесткий диск, `sdb1` — первая флешка).
3.  **Процессы и система** — виртуальные файлы в `/proc/`. Хотите узнать, какой процессор? Читайте файл: `cat /proc/cpuinfo`. Хотите посмотреть, какие аргументы запуска у процесса PID=1234? Читайте `cat /proc/1234/cmdline`.
4.  **Логи** — текстовые файлы в `/var/log/`.

**Где что лежит (стандарт FHS):** Выучите эти 5 папок:

| Путь        | Назначение                                    | Что там искать?                         |
| :---------- | :-------------------------------------------- | :-------------------------------------- |
| `/`         | Корень всей системы.                          | Начало пути (слеш).                     |
| `/home/`    | Домашние папки пользователей.                 | Проекты, загрузки, настройки.           |
| `/etc/`     | **Конфигурации** (самое важное для инженера). | Настройки сервисов (nginx, sshd, cron). |
| `/var/log/` | **Логи** (журналы событий).                   | Если что-то упало — смотри сюда.        |
| `/tmp/`     | Временные файлы.                              | Очищается при перезагрузке.             |

## 1.3. Анатомия прав доступа (безопасность)

Linux многопользовательская система. Чтобы один стажер не положил сервер, есть строгая система прав. Каждый файл принадлежит **Владельцу (User)** и **Группе (Group)**.

Смотрим права командой `ls -l`:
`-rw-r--r-- 1 root root 1234 Jun 26 10:00 myfile.txt`

Разберем магию `-rw-r--r--` (10 символов):

1.  **Первый символ** — тип:
    *   `-` = обычный файл.
    *   `d` = папка (directory).
    *   `l` = ссылка (link).
2.  **Следующие 9 символов** — это три блока по 3 символа (`rwx`).
    *   **1-3** (`rw-`): Права **Владельца**.
    *   **4-6** (`r--`): Права **Группы**.
    *   **7-9** (`r--`): Права **Остальных (All)**.

**Что означают буквы:**

| Буква | Для ФАЙЛА | Для ПАПКИ |
| :--- | :--- | :--- |
| **r** (read) | Читать содержимое. | Читать список файлов в папке (только с `x`). |
| **w** (write) | Изменять/писать в файл. | **Создавать и удалять** файлы внутри папки. |
| **x** (execute) | Запускать как программу/скрипт. | Зайти внутрь папки (`cd folder`). |

**Числовой способ (самый быстрый):**
Каждой букве соответствует число: `r=4`, `w=2`, `x=1`.
Складываем для каждой группы (Владелец/Группа/Остальные).

*   `7` = 4+2+1 (полный доступ, rwx)
*   `6` = 4+2 (чтение и запись, rw-)
*   `5` = 4+1 (чтение и выполнение, r-x)
*   `4` = 4 (только чтение, r--)

**Золотые стандарты (запомните на всю жизнь):**
*   `chmod 755 script.sh` — **Стандарт для скриптов**.
    *   Владелец: `7` (читает, пишет, выполняет).
    *   Группа и Остальные: `5` (только читают и выполняют, НЕ редактируют).
*   `chmod 644 file.txt` — **Стандарт для конфигов**.
    *   Владелец: `6` (читает и пишет).
    *   Остальные: `4` (только читают).
*   `chmod 600 ~/.ssh/id_rsa` — **Стандарт для приватных ключей SSH**.
    *   Только владелец имеет полный доступ. Никто другой не должен его даже читать, иначе SSH ругается и не работает!

**Важное предупреждение для папок:** Чтобы создать или удалить файл в папке, вам нужно иметь право **w (write)** на *саму папку*, а не на файл внутри! Если у вас есть `x` (доступ войти) и `w` (запись) на папку, вы можете удалить файл, даже если у вас нет прав на запись в сам этот файл.

**Сменить владельца файла (или группу):**
`chown` позволяет передавать права собственности на объекты от одного пользователя или группы к другому, нужно запускать от администратора.
`sudo chown новый_пользователь:новая_группа файл`
- рекурсивно изменить владельца для каталога:
`sudo chown -R john:docs /var/www/project`
- скопировать права с `reference_file` на `new_file:` 
`sudo chown --reference=reference_file new_file`

## 1.4. Три потока данных (STDIN, STDOUT, STDERR)

Это основа, без которой вы не поймете логирование. Когда команда запускается, у нее есть 3 «трубы»:

1.  **STDIN (0)** — Ввод (обычно клавиатура).
2.  **STDOUT (1)** — Стандартный вывод (результат команды).
3.  **STDERR (2)** — Стандартный вывод ошибок (сообщения об ошибках).

По умолчанию и `1` и `2` выводятся в ваш терминал, чтобы вы видели текст. Но мы можем их перенаправить:

*   `ls > files.txt` (`>` перенаправляет поток **1** (STDOUT) в файл, перезаписывая его).
*   `ls >> files.txt` (`>>` добавляет STDOUT в конец файла).
*   `ls -la /nonexist 2> error.log` (`2>` перенаправляет поток ошибок в файл, а на экране будет чисто).
*   `command > output.txt 2>&1` — **Самый частый прием в скриптах**. Означает: *«Перенаправить STDOUT в файл, а STDERR (2) отправить туда же, куда и STDOUT (>&1)»*. В итоге в файл попадет и лог, и ошибки.

## 1.5. Шпаргалка по командам для этого блока

```bash
# Посмотреть ядро и архитектуру
uname -a

# Посмотреть, где лежит сама программа Bash
which bash

# Узнать права файла
ls -la /etc/passwd

# Сменить права (сделать исполняемым для всех)
chmod +x my_first_script.sh   # (+x добавляет флаг выполнения, аналог 755)

# Сменить владельца всей папки
sudo chown -R user:usergroup /var/www/project

# Посмотреть информацию о процессоре (читаем файл!)
cat /proc/cpuinfo | grep "model name"

# Перенаправить ошибку в пустоту (/dev/null — черная дыра Linux)
rm -f /root/secret 2>/dev/null
```
